# DeepSeek Text-to-SQL, Analytics & Auto-Charting Studio

An AI-powered Text-to-SQL application that converts natural-language questions into executable SQL queries using DeepSeek API. Built with Python, SQLite, Pandas, Matplotlib, and Gradio, the application enables users to upload database schemas, import CSV datasets, generate SQL queries, execute them automatically, correct execution errors, and obtain AI-generated analytical insights.

---

## 1. Project Overview

Working with relational databases often requires familiarity with SQL syntax, database structures, and query optimization. This creates a barrier for users who want to retrieve and analyse information without extensive SQL knowledge.

This project addresses that challenge by developing an AI-powered Text-to-SQL system that allows users to interact with databases using simple English instructions.

Users can provide their database structure through an Entity Relationship (ER) diagram, a schema screenshot, SQL DDL statements, or CSV files. The application processes the provided information, establishes a live SQLite database, and uses DeepSeek models to translate natural-language questions into SQL queries.

The generated queries are automatically executed against the database. If execution fails, the system feeds the error information back to the language model and attempts to generate a corrected query.

Beyond query execution, the application also generates plain-English summaries and automatically creates visualizations when the returned data is suitable for charting.

## 2. Key Features

### A. Database Schema Extraction

The application supports two methods of database schema creation:

- **Image-Based Schema Extraction:** Upload an ER diagram or database schema screenshot. DeepSeek Flash analyses the image and extracts tables, columns, data types, primary keys, and foreign-key relationships.
- **SQL DDL Input:** Paste SQL `CREATE TABLE` statements directly into the application to establish the database structure.

The extracted or supplied schema is executed against SQLite to create the active database tables.

### B. CSV Data Ingestion

Users can upload one or multiple CSV files simultaneously.

The application automatically:

- Reads the uploaded CSV files using Pandas.
- Converts filenames into database table names.
- Sanitizes column names to produce SQLite-compatible identifiers.
- Creates corresponding database tables.
- Imports the CSV records into SQLite.
- Retrieves the updated database schema.

Each uploaded CSV file is treated as a separate database table.

### C. Natural Language to SQL Conversion

Users can ask questions about their database in ordinary English.

For example:

- Show the total revenue generated by each product category.
- Find the top five customers based on their purchase amounts.
- Calculate the average salary of employees in each department.
- Show monthly sales trends for 2025.
- Identify customers who have placed more than three orders.

The DeepSeek model receives the active database schema along with the user's question and generates the corresponding SQLite query.

### D. Multiple DeepSeek Model Options

The application provides two model configurations:

| Model | Purpose |
|---|---|
| `deepseek-chat` | Standard SQL generation and analytical tasks |
| `deepseek-reasoner` | More complex queries requiring additional reasoning |

The application also uses `deepseek-flash` for image-based schema extraction.

### E. Automatic SQL Execution

The generated SQL query is automatically executed against the active SQLite database.

The application supports:

- SELECT queries.
- Common Table Expressions (CTEs).
- PRAGMA statements.
- EXPLAIN statements.
- Other executable SQL statements, including database modifications.

Query results are returned as Pandas DataFrames whenever applicable.

### F. Self-Correction Mechanism

One of the central features of this project is its automatic SQL error-correction loop.

Instead of stopping immediately when a generated query fails, the application captures the SQLite execution error and sends it back to the language model.

The model then attempts to generate a corrected query using the original database schema and the execution error as additional context.

The number of automatic correction attempts can be configured through the Gradio interface.

The default configuration allows three correction attempts.

### G. AI-Powered Result Summarization

After successful execution of a SELECT query, the application sends the query results to DeepSeek for interpretation.

The model generates a concise, plain-English summary highlighting relevant figures, rankings, and patterns.

The summarization process uses the first 30 rows of the returned DataFrame as its input.

### H. Automatic Data Visualization

The application includes an automatic chart-generation mechanism built using Matplotlib.

Depending on the structure of the returned dataset, it attempts to generate:

- **Line Charts:** For datasets containing temporal or date-related columns.
- **Bar Charts:** For datasets containing categorical and numerical variables.

The visualization engine identifies suitable numerical columns and selects up to two numerical series.

It also adjusts chart orientation and limits displayed records to improve readability.

If the returned dataset is unsuitable for visualization, the chart is automatically omitted.

## 4. System Architecture

The application follows a multi-stage processing pipeline.

**Stage 1: Input Acquisition**

The user provides the database structure through an ER diagram, SQL DDL statements, or CSV files.

**Stage 2: Schema Processing**

The application extracts or applies the schema and establishes the corresponding SQLite database.

**Stage 3: Natural Language Processing**

The user submits a question in plain English. The active schema and question are passed to the selected DeepSeek model.

**Stage 4: SQL Generation**

The language model generates an SQLite-compatible SQL query using the available database structure.

**Stage 5: Query Execution**

The generated SQL statement is executed against the active SQLite database.

**Stage 6: Automatic Error Correction**

If execution fails, the error is returned to the language model for query correction. This process continues until execution succeeds or the configured retry limit is reached.

**Stage 7: Result Analysis**

Successful query results are processed using Pandas and passed to DeepSeek for natural-language summarization.

**Stage 8: Visualization**

Matplotlib automatically generates a suitable chart whenever the returned dataset meets the visualization criteria.

**Stage 9: Output Presentation**

The application displays the generated SQL, execution trace, analytical summary, visualization, and query results through the Gradio interface.

## 8. Important Implementation Details

- The application creates a temporary SQLite database for each Gradio session.
- The active database schema is retrieved directly from SQLite's internal `sqlite_master` table.
- SQL generation is schema-aware, meaning the language model is instructed to use only the available tables and columns.
- Generated queries are cleaned to remove accidental Markdown code fences.
- SQL execution errors are incorporated into subsequent model prompts for automatic correction.
- Result summarization uses a maximum preview of 30 records.
- Automatic visualization requires at least two returned rows and suitable numerical columns.
- The Gradio application is launched with sharing enabled using `share=True`.

**Security consideration:** The current implementation executes generated SQL statements, including non-SELECT statements. It does not implement a comprehensive SQL permission or read-only security layer. Therefore, use trusted database inputs and avoid connecting sensitive production databases without additional safeguards.

## 9. Current Limitations and Future Scope

The present implementation establishes a functional foundation for an AI-powered Text-to-SQL and database analytics application.

Several improvements can further enhance its capabilities:

1. **PostgreSQL Integration:** Replace SQLite with PostgreSQL to support advanced relational database operations and PostgreSQL-specific SQL syntax.
2. **Multiple Database Support:** Introduce support for MySQL, PostgreSQL, MariaDB, DuckDB, and Microsoft SQL Server.
3. **Advanced Query Validation:** Implement SQL parsing, validation, and permission checks before execution.
4. **Query Optimization:** Introduce query analysis and optimization recommendations.
5. **Database Explorer:** Add interactive table browsing, schema visualization, and relationship exploration.
6. **Query History:** Maintain a searchable history of previously generated and executed queries.
7. **Advanced Analytics:** Integrate statistical analysis and more sophisticated visualization techniques.
8. **Multi-Agent Architecture:** Introduce specialized agents for schema understanding, SQL generation, query validation, execution, and result interpretation.
9. **Persistent Storage:** Support persistent databases and user-specific workspaces.
10. **Production Deployment:** Introduce authentication, secure database connections, logging, and cloud deployment.

These are proposed enhancements and are not part of the current implementation.
